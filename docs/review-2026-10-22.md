# Historical 0.1.4 review and user workflow check

Review date: 2026-10-22. Source baseline: c76054d70d6b48c9aaccfb5ac370f8fe7cdf442e, matching the then-read 0.1.4 latest manifest. This historical review changed documentation/demo, not the official CLI/installers or immutable release files.

Subsequent native Windows feedback led to fixes in 0.1.5 and later. The findings below describe the reviewed baseline, not unresolved defects in current source. See [recovery](windows-0.1.4-recovery.md) and [verification](verification.md).

## P2: Linux download failure could return success

The reviewed generator used curl piped into sudo sh. Without pipefail, curl failure producing no script could leave sh successfully executing an empty input, reporting exit 0.

The actual makeCommand output was executed with curl returning 22 and sudo replaced by a non-elevating forwarder. The observed pipeline exit was 0 with the simulated download error. This was a reproduction, not an inference.

The recommendation was to propagate both download and installer failures and cover empty/truncated/error paths. The historical guide's operator-side Bash pipefail workaround did not itself fix the implementation. Later source generates a pipefail command.

## P2: Windows private/public NTFS boundary was missing

The reviewed installer created its program directory and called setup without native ACL separation or actual anonymous-identity discovery. IIS mapping/rules alone did not grant correct filesystem reads. Windows chmod mode 0600 did not establish a Unix-style private ACL.

Two distinct outcomes were possible: restricted resources failed anonymous SDK access and deployment rolled back; broadly inherited state could remain readable despite a 0600 mode. This did not imply every host failed installation or had identical exposure.

The recommendation was to protect private state for administrators/SYSTEM, grant only public-resource reads, and verify failure recovery did not broaden existing permissions. Native Windows testing was required; Linux PowerShell mocks were not NTFS evidence. Later source implements the corresponding DACL/public-identity boundary.

## Documentation corrections in the review

- Replace reliance on a release-directory README index with the actual package/manifest/checksum layout.
- Distinguish discovery server+[rum] configuration from complete [[sites]] configuration.
- Explain temporary installer TOML cleanup and operator retention of ID/state.
- Use stable config/state/site selectors for manual steps.
- Explain that manual Nginx attachment has no automatic original-file backup and cannot promise automatic attachment rollback.
- Provide an operator ACL diagnosis path pending implementation changes.
- Obtain test scripts from matching source tags, not platform archives; ordinary installation needs no Git.
- Clarify Linux-only automatic Nginx scope.
- Distinguish script success, HTML injection, browser requests, and real stored events.

## Reviewed paths and limits

| Path | Finding/boundary |
| --- | --- |
| Download/release | Pinned version/digests; no Git needed; later docs do not rewrite old files |
| Configuration page | Gateway/direct modes, complete/discovery formats, release capabilities |
| Discovery/setup | Stable identity, post-choice recheck, terminal ambiguity refusal |
| Nginx | MIME/path/compression/assets; complex layouts need manual review |
| IIS | Native rules/mappings/compression and transaction ownership; ACL gap above at this baseline |
| Lifecycle | Recovery journals, resources retained for cached HTML, attachment rollback separate |
| Identity | Site/server/state binding prevents takeover through a new state root |
| OTel | Separate component/dependency configuration; no new end-to-end evidence in this review |
| Acceptance | Status/probe, browser execution/upload, and real backend readback are separate layers |

No new Nginx lifecycle failure was exposed by these checks. They did not exhaust every server configuration. IIS native commit and local journaling have an unavoidable non-atomic window; ambiguous ownership retains evidence for review rather than claiming universal automatic recovery.
