# Nginx 普通 head 注入

Nginx 新启用或更新 RUM 配置时统一匹配 `<head>`，大小写不敏感，因此 `<HEAD>`、`<Head>` 同样受支持。带属性、结束括号前空白/换行/Tab、自闭合和缺失 head 均不在支持范围。标签之前不能有相同的伪标签文本；预检会拒绝这种歧义。固定字符串过滤器不是 HTML 解析器，检查页通过不代表未检查页面或后续模板变更已验证。

`includePaths`、`excludePaths` 决定注入范围。`probePaths` 只选择 HTTP 验收页面，不学习标签、不生成逐路径规则；未列入检查路径的普通 head 页面仍可注入。IIS 保持原有普通 head 边界。

不增加模块、配置开关或安装参数。保留 0.1.9 的 Range 和 CDN SDK 修复。

0.1.9 已部署配置不会因替换 CLI 而自动变化。更新 RUM 时，除配置的检查路径外，还核对旧快照中仍在注入范围内的属性标签路径；不兼容则在修改配置前停止，保留原部署。原页面调整为普通 head 后可更新。禁用、仅调整 OTel 和回滚继续读取旧快照，保留旧规则所需的信息。更新成功后生成普通 head 规则，不保留路径依赖。

验证覆盖：普通/大写/混合大小写 head、多页面与 query、未检查路径、排除路径、属性和空白拒绝、失败保持原部署、0.1.9 迁移及禁用/回滚、Range/缓存、CDN 生命周期。浏览器验收使用本地合成页面与本地接收端，不向共享空间写入数据。

## 验证结果

本地 Go 1.20.3、原生 Nginx 1.24.0（sub_filter/PCRE，无新增模块）：普通 head/大小写、多页面与 query、排除、属性/空白拒绝、probePaths 不改变注入规则、0.1.9 更新失败保护及迁移/禁用/回滚、Range 和 CDN 生命周期定向集成测试各连续三轮通过。全量 Go 测试、go vet、CLI 构建通过。

Chrome 中使用本地 CLI 生成并启用的真实 Nginx 配置与内嵌 SDK：异步模式首页和未列入 probePaths 的第二页均初始化成功；同步模式混合大小写页面初始化成功；属性 head、带空格 head 和排除页面均未插入脚本。本地接收端返回 202，未验证共享空间入库。页面提示在高级设置外显示，六语言在 PC 与 390px 窄屏下可见、无文字溢出并可换行；Client 配置、组件、locale 三套测试通过。
