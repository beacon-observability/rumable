# v0.1.10

Fix empty IIS application pool OTel environment snapshots blocking enable and rollback, and add multilingual browser setup.

## Changes

- Fix [#4](https://github.com/beacon-observability/rumable/issues/4): explicitly enumerate snapshot properties in comparison, equality, and restoration. Empty JSON objects now match empty live dictionaries, while existing key/value checks and unrelated pool settings remain protected.
- Add regression coverage on Windows PowerShell 5.1 and PowerShell 7 for empty/nonempty snapshots, changed keys and values, restoration, and idempotency.
- Add English, Simplified Chinese, Traditional Chinese, Indonesian, Japanese, and Korean setup interfaces.
- Support GitHub RC publication without changing stable latest aliases or deploying RC configuration pages.

## Validation

The v0.1.10-rc.1 release workflow passed dual-compiler tests, ten Linux/Windows package checks, packaged CLI integration with Nginx, Windows AMD64 modern/legacy execution, and PowerShell contracts.

The operator reported native regression success using the official RC without local patches or frontend changes: first enable from an empty pool environment, rollback restoring that empty environment, and re-enable all succeeded. RUM uploads and session replay uploads succeeded (8 segments, 23 records). Browser and server spans shared a trace ID, and the server parent span ID matched the RUM span ID. These results validate the RC's core IIS fix; the final stable packages are rebuilt and checked independently by the release workflow.

## Known limitations

- The separate managed-agent `dependency ownership mismatch` observation in #4 was not reproduced in the reported RC run and is not claimed fixed. Explicit `agentPath` remains an option for isolating managed installation from the snapshot fix.
- The session replay playback UI was not manually revalidated in that run; successful replay upload does not establish playback UI acceptance.
- Existing state is not automatically recovered by installing this release. Retain deployment state backups and use the ordinary recovery/rollback commands with the updated CLI.
