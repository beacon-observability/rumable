# v0.1.11

Fix Nginx injection scope, Range handling, and first-time CDN attachment while retaining the GitHub release channel, multilingual setup, and IIS OTel fixes from v0.1.10.

## Changes

- Match plain `<head>` case-insensitively throughout the configured Nginx injection scope. `probePaths` selects verification pages only; it no longer generates per-path injection rules. Attributes and extra whitespace inside the tag remain unsupported. No new module or installation option is required.
- Preserve legacy 0.1.9 snapshot disable, OTel-only operations, and rollback. RUM updates check saved attribute-head paths still in scope and stop before changing incompatible deployments.
- Bypass Rumable injection for Range requests, preserving origin range handling and existing cache safeguards.
- Validate the actual stable v3 CDN SDK during check/enable and save its version, URL, and SHA-256. It need not match the bundled SDK. Deployed probes and rollback still require the saved digest; optional SRI uses the activation digest.
- Fix first automatic CDN attachment and retry after a restored installation failure. Retain offline disable and avoid an automatic local-SDK fallback.
- Update English documentation and localized setup guidance for CDN changes and verification scope.

## Validation

The synchronization passed full Go tests with native Nginx integration on Nginx 1.24.0, Go vet, SDK/release script tests, 45 Node tests, and documentation checks using Go 1.26.4 and Node 24.16.0. Release workflows independently run both Go compilers, verify ten platform archives, exercise the packaged Linux CLI with Nginx, and check Windows AMD64 modern/legacy execution and PowerShell contracts before publication.

Native IIS acceptance and live receiver ingestion were not repeated for this release. Prior v0.1.10 IIS acceptance remains historical evidence; this release does not claim to fix the separate managed-agent ownership mismatch observation.

## Upgrade notes

Keep the original site ID, target definitions, state directory, and old assets. Replacing the CLI alone does not change deployed sites; reapply setup or enable to update RUM. Review [plain head support](../nginx-plain-head.md) before updating older Nginx deployments. A mutable CDN can change browser-delivered content; re-enable to validate and record new bytes. Format checks and hashes do not establish SDK provenance or collection compatibility. Validate browser collection and replay after SDK changes.
