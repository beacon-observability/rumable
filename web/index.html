02

Choose how to load the SDK

The server injects scripts into HTML. The browser loads and initializes the SDK using your selected method.

The SDK is bundled with Rumable and served from your website's origin. Browsers do not need an external CDN.

Cross-origin SRI requires CDN CORS support. It is off by default for the package-default source. Enable it for a compatible immutable CDN URL after verification.

The initialization script and SDK load asynchronously without blocking HTML parsing. Errors, requests and interactions before initialization may not be captured.

How SDK updates work

The same-origin SDK is pinned to the package. After installing a newer Rumable package, run setup or enable again for the original site to update it. Downloading or replacing the CLI alone does not update the site. Keep old assets for rollback.

Application version labels your application release. SDK remote configuration adjusts collection settings. Neither updates the SDK files.

03

Choose what to collect

The SDK automatically collects performance, resource and error data. Configure sampling and recording below.

RUM sessions are sampled before replay recording is selected. Your site's CSP must allow the required Worker.

Advanced Web SDK settings

Remote configuration may override static settings. setUser, custom startView and beforeSend require application code and are not implemented by server injection.

04

Choose your server environment

The installation command discovers websites on your server.

Requires Bash, curl and sudo. Installation detects Linux x86 (32-bit), x64 or ARM64 automatically.

A single site is selected automatically. Choose in the terminal when there are multiple sites or URLs. If the hostname cannot be determined, you will be prompted for the URL. All paths of the selected site or application are included by default.

Advanced setup (optional)

If unchecked, discovery asks for permission when changes are needed. Disabling or uninstalling restores the original settings.

Pages need a standard <head> opening tag. Deployment checks CSP, SDK conflicts and verification pages. On incompatibility, it stops and keeps recovery records.

IIS requires URL Rewrite, static resource read permissions and a dedicated application pool. Enable, update, disable and rollback recycle that pool and may lose in-memory sessions; shared pools are refused. Run PowerShell 5.1+ as administrator. The installer detects x64 / ARM64 and the Windows version, selecting a legacy package for older systems. One-click IIS setup does not support 32-bit Windows.
